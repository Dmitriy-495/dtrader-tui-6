# dtrader-tui-6

Терминальный клиент dtrader-6. Читает данные из `ws-server` (см.
`github.com/Dmitriy-495/dtrader-6`) и отображает их в реальном времени.

## Статус: полноценный главный лайаут, MVP пройден

Проект начат с нуля 2026-08-17 (предыдущая версия локально накопила
слишком много правок разными руками, решено переписать заново —
см. CHECKPOINT.md dtrader-6, раздел 16). С тех пор пройден путь от
проверки связности до полноценного главного лайаута с несколькими
вкладками, настраиваемыми пропорциями панелей и покрытием тестами.

Связность и весь протокол подтверждены вживую на проде (msk),
включая реальные обрывы соединения и автореконнект — не только
в юнит-тестах.

### Что реализовано

**Главный лайаут** (header + tabs + [content|rightbar] + footer,
раздел 9 CHECKPOINT.md dtrader-6):
- **Header** — три строки (рамка+контент+рамка): бренд, время,
  баланс+PnL по центру, статусы SERV/EXCH по порогам раздела 11.
- **Tabs** — Dashboard (вкладка №0) + по одной вкладке на каждый
  символ, формируются один раз при получении первого `system`-
  сообщения (`symbols`), не пересоздаются при повторных.
  Навигация: `Tab`/`Shift+Tab` по кругу, `Ctrl+1..9` — прямой переход.
- **Dashboard** — обзор всех символов блоками: заголовок (символ +
  midprice + двусторонняя шкала pressure) + три строки по
  таймфреймам (1m/8m/24m) с трендом и объёмной дельтой. Собственная
  прокрутка (`bubbles/viewport`).
- **Вкладка символа** — полная карточка: стакан (20 уровней с
  полосами глубины) слева, T/V/P по трём таймфреймам справа
  (двусторонние шкалы: центр=0, влево/вправо по знаку), best bid/ask
  в шапке. Собственная прокрутка.
- **Rightbar** — LOGS (свой viewport, автоскролл к последней записи —
  не растёт бесконечно при долгой работе, критичный баг найден и
  исправлен на реальном прод-логе за ночь работы) + POSITIONS
  (отдельный всегда видимый блок снизу, разделитель сверху).
- **Footer** — подсказки горячих клавиш, тот же стиль рамки, что
  header.
- **Настройки лайаута** (`layout.yaml`) — пропорции панелей
  (`rightbar_width_percent`, `positions_height_percent`,
  `news_height_rows`) вынесены из кода в отдельный YAML-файл,
  перечитывается при старте TUI (без hot-reload — решение принято
  явно). Отсутствие файла — не ошибка, используются дефолты 40/40/10;
  битый или невалидный файл — явная ошибка при старте, не тихий откат.

**Данные:**
- `internal/config` — `.env` (`WS_SERVER_URL`, `WS_API_KEY`).
- `internal/ws` — клиент ws-server: авторизация (`X-API-Key`), чтение
  `{channel, symbol, data}`, автопереподключение (3s), read-timeout
  (30s) на случай "тихого" обрыва без close-фрейма (актуально на
  нестабильной/мобильной связи).
- `internal/indicators` — типы каналов `indicators` (T/V/P),
  `orderbook`, `system` (баланс, PnL, символы, позиции) — сняты с
  реальных прод-ответов, не выдуманы по документации.
- `internal/tui/app.go` — единственный читатель `client.Messages`;
  раздаёт сообщения по вкладкам символов через их `Update()` (не
  каждая вкладка сама слушает канал — иначе они конкурировали бы за
  сообщения).

### Известные ограничения / не реализовано

- **Новостная лента** — задел есть (`news_height_rows` в настройках),
  сама лента не реализована. Источник выбран и подтверждён: CryptoPanic
  API (`CRYPTOPANIC_API_KEY` уже в `internal/config`, не используется
  пока) — независимая команда, активно поддерживается на 2026 год,
  кэш на сервере — опрашивать не чаще раза в 30с.
- **Реконнекты каждые несколько минут** замечены в живом прод-логе за
  ночь работы (не диагностировано — стабильность сети до/от ws-server,
  а не баг TUI, обсуждение отложено).
- **Формирование торговых сигналов** — не начато, это следующий
  крупный этап проекта (см. PROMPT_NEXT.md).

## Запуск

```bash
cp .env.example .env
# заполнить WS_SERVER_URL (адрес msk или sgp) и WS_API_KEY

go mod tidy   # первый раз — подтягивает зависимости и создаёт go.sum
go build -o dtrader-tui-6 ./cmd
./dtrader-tui-6
```

`go.sum` намеренно не включён в архив — песочница разработки не имеет
доступа к оригинальным модульным прокси (`proxy.golang.org`,
`go.yaml.in`), поэтому любой `go.sum`, сгенерированный там, ссылался
бы на временные github-зеркала, а не на настоящие пакеты. `go.mod`
чист (никаких `replace`) — `go mod tidy` на твоей стороне с открытым
интернетом создаст правильный `go.sum` за секунды.

`layout.yaml` опционален — без него используются дефолты (40/40/10).
Чтобы изменить пропорции панелей, скопируй и отредактируй пример,
уже лежащий в корне репозитория, затем перезапусти TUI.

Готовые бинарники — в `dist/` (`dtrader-tui-6-linux-amd64`,
`dtrader-tui-6-darwin-arm64`), собраны в песочнице разработки, не
проверялись на реальном железе — собери из исходников, если есть
сомнения.

## Горячие клавиши

- `Tab` / `Shift+Tab` — следующая/предыдущая вкладка
- `Ctrl+1`..`Ctrl+9` — прямой переход к вкладке по номеру
- `↑`/`↓`, `PgUp`/`PgDn` — прокрутка активной вкладки (Dashboard или символ)
- `Ctrl+L` — принудительная полная перерисовка экрана (обходит
  редкую рассинхронизацию рендера, если сторонний `Ctrl+L` дошёл до
  терминала раньше приложения)
- `q` / `Ctrl+C` — выход

## Тесты

```bash
go test ./...          # 73 теста
go test -race ./...    # с детектором гонок данных — чисто
```

Тесты используют реальные JSON-снапшоты с прода (не выдуманные
структуры), плюс интеграционные тесты с настоящим TCP через
`httptest` для проверки read-timeout и реконнекта в `internal/ws`.
